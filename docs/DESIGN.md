## общее

- два крейта: `rosea-core` (логика без окна) + `rosea-app` (CLI + minifb)
- `rosea-core` должен собираться headless - иначе тесты в CI не запустить
- сторонние зависимости: `lzma-rs` для распаковки `.osr`, `minifb` для окна, Criterion только для замеров; остальное — свой код на `std`
- `Cargo.lock` в репо
- никакого unsafe в коде
- никаких HashMap в игровой логике - только Vec + сортировка, иначе недетерминизм

## ЧД

### 1. Парсеры
- парсер `.osu` v14, только Mode 0
- парсер `.osr` - little-endian, ULEB128 (без знака), bitmask кнопок, пока lzma-rs для распаковки
- тесты на позитивные и негативные случаи для обоих

### 2. Геометрия и подготовка карты
- linear / Bézier (составной) / circular arc для слайдеров
- stacking v14 - внимательно сверить логику обратного прохода и сдвига координат со stable перед реализацией
- подготовка должна быть один раз на прогон, рендерер ничего не пересчитывает

### 3. Симулятор
- круги, слайдеры L/B/P с повторами, спиннеры
- ScoreV1 + combo
- сравнение результата с заголовком `.osr` по 6 полям, JSON-отчёт

### 4. Рендер и вывод
- CPU-растеризатор: диски, кольца, полилинии, alpha blend
  - `(src*a + dst*(255-a) + 127) / 255` на канал
  - буфер `Vec<u32>` формата `0x00RRGGBB`, row-major
  - дефолт 1024×768, логический холст 640×480, поле смещено на (64, 48)
- окно через minifb: пауза Space, выход Escape
- экспорт PPM P6 и Y4M C444 - потоково, без накопления кадров в памяти
- Criterion бенчи на растеризатор

### 5. Финал
- прогнать весь корпус (31 пара в `tests/data/`), опубликовать отчёты
- smoke-тест окна на Windows и macOS
- видеодемо

## Важность

- типы: координаты f32, время/длины/углы f64, score u64, combo u32 - всё checked
- `game_version` в `.osr` это i32 версия клиента, не версия формата - не использовать для выбора алгоритма
- MD5 карты считается от сырых байт до парсинга, включая BOM
- служебная запись `-12345` в реплее не прибавляется к накопленному времени
- stacking сдвигает координаты везде одинаково - и для hit testing и для рисования, спиннер не трогает
- `slides` в `.osu` это число spans, разворотов на один меньше
- threshold хвоста `-36 мс` - не менять значение, пока не обкатаем базовый трекинг слайдеров на тестовых реплеях
- hit windows: `floor` в целые мс, проверка строго `<` (`dt < W300` -> 300, `dt < W100` -> 100, `dt < W50` -> 50, иначе miss при `t >= start + W50`)
- спиннеры: расчет полуоборотов `floor(angle / pi)`, порог 300 `req_half + 1`, бонусы 1100/100, кап 477 RPM не эмулируем (чистая геометрия по спецификации)
